# Threat model

Agent Governor protects workstation availability from accidental concurrency among cooperative local
agents. It is not intended to resist a malicious user or process running under the same account.

## Protected properties

- A recognized heavy command does not start without a held healthy slot.
- Hook input cannot become shell syntax generated by Agent Governor.
- RTK and workload subprocesses receive arguments directly.
- Commands, arguments, environment, paths, and transcripts are not persisted.
- Installer writes preserve unrelated settings and use private backups.

## Out of scope

- A user or agent deliberately invoking the underlying tool outside the hook.
- Deleting user-owned hooks or stable lock files.
- Builds started by Terminal, IDE tasks, or processes already running.
- Isolation between different macOS users.
- Controlling, bypassing, or modifying EDR, DLP, proxy, or privilege software.

## Defensive choices

- bounded inputs and outputs;
- CST-based insertion instead of whole-command regex rewriting;
- private runtime directories and files;
- stable per-slot lock inodes with close-on-exec behavior from Rust file opens;
- macOS kernel `MNT_LOCAL` validation before runtime creation and scheduler admission;
- corrupt metadata quarantines one slot rather than being deleted;
- exact opaque job IDs and held-lock validation before cancellation;
- no project-local configuration trust by default;
- no runtime network access or telemetry.
